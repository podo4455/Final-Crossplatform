## วิธีใช้

กด **เลือกรูปภาพ (เลือกได้หลายรูป)** ใช้ Ctrl บน Windows หรือ Command บน macOS คลิกเลือกรูป หรือ Shift เลือกเป็นช่วง แล้วเลือกโฟลเดอร์ปลายทางและเริ่มสำรอง
คัดลอกเฉพาะรูปที่เลือกลงปลายทางโดยตรง เก็บต้นฉบับไว้ และข้ามชื่อซ้ำ
กด **เปลี่ยนรูปที่เลือก** เพื่อเลือกชุดใหม่ การเลือกใหม่แทนชุดเดิม ส่วนการยกเลิกจะเก็บชุดเดิมไว้
หน้า UI แสดงจำนวนและรายการรูปที่เลือก ไม่มีตัวเลือกสำรองทั้งโฟลเดอร์
API ที่หน้า UI ใช้คือ `SelectPhotos()` และ `BackupSelectedPhotos(paths, destination)`
ส่วน service สำหรับหลายไฟล์/โฟลเดอร์ด้านล่างยังเก็บไว้ แต่หน้า UI ไม่ได้เรียกใช้

รัน `wails dev` ที่ root โปรเจกต์ เปิดเมนูสำรองรูป เลือกรูปที่ต้องการและโฟลเดอร์ปลายทางที่มีอยู่แล้ว แล้วกดเริ่มสำรองรูปภาพ
แอปค้นหารูปในโฟลเดอร์ย่อยและคงโครงสร้างเดิม เช่น `DCIM/Trip/a.jpg` จะถูกคัดลอกเป็น `<ปลายทาง>/DCIM/Trip/a.jpg`

- คัดลอกเท่านั้น ไม่ลบหรือย้ายต้นฉบับ
- รองรับนามสกุล JPG/JPEG/PNG/GIF/WebP/BMP/TIF/TIFF/HEIC/HEIF/AVIF โดยไม่แยกตัวพิมพ์เล็กใหญ่ ยังไม่ได้ตรวจเนื้อหาว่าเป็นภาพจริง
- ข้ามไฟล์ปลายทางที่มีชื่ออยู่แล้ว ไม่ตรวจความเหมือนของเนื้อหาและไม่เขียนทับ
- ปฏิเสธโฟลเดอร์เดียวกันหรือซ้อนกันทั้งสองทิศทาง ข้าม symbolic links ในต้นทาง และจำกัดการเขียนอยู่ใต้โฟลเดอร์ปลายทางด้วย `os.Root`
- คัดลอกทีละไฟล์ด้วย buffer ไม่โหลดภาพทั้งหมดเข้า RAM; แสดงความคืบหน้าตามจำนวนไฟล์
- ถ้าบางไฟล์คัดลอกไม่สำเร็จ รายงานข้อผิดพลาดและทำไฟล์ถัดไป ลบเฉพาะไฟล์ปลายทางที่สร้างใหม่และคัดลอกไม่สมบูรณ์เมื่อจัดการข้อผิดพลาดได้
- หากแอปถูกบังคับปิดหรือไฟดับ อาจเหลือไฟล์ไม่สมบูรณ์ ต้องตรวจไฟล์ก่อนสำรองซ้ำ เพราะนโยบายชื่อซ้ำคือข้าม
- โทรศัพท์ต้องเข้าถึงได้ผ่าน filesystem; ไม่รองรับ MTP/PTP โดยตรง ให้ใช้เครื่องมือนำเข้ารูปของระบบก่อน
- ใช้ Go API ข้ามแพลตฟอร์ม ไม่มี drive letter แบบตายตัว ต้องทดสอบอุปกรณ์จริงและ build บน macOS แยกต่างหาก

## จุดเชื่อมกับส่วนที่ 2 และ 3

`BackupPhotos(source, destination)` คืน `service.Result`:
`total`, `copied`, `skipped`, `failed`, `files`.
แต่ละไฟล์มี `source`, `destination`, `size` (จำนวน bytes ที่เขียน),
`status` (`copied`, `skipped`, `failed`), `error`, `copiedAt` (UTC RFC3339 เฉพาะที่สำเร็จ)
ส่วนฐานข้อมูลสามารถบันทึกเฉพาะรายการ `copied` และส่ง `destination` ให้ส่วนวิเคราะห์ภาพต่อได้
ผลลัพธ์ตอนนี้อยู่ในหน่วยความจำและบนหน้าจอ ยังไม่มีการบันทึกประวัติ SQLite/GORM หรือ Tag

Event `backup:progress` ส่ง `{total, completed, current}` หลังสแกนและหลังแต่ละไฟล์
Wails สร้าง bindings ด้วย `wails generate module`; ไม่แก้ generated bindings ด้วยมือ

## ตรวจสอบ

```sh
go test ./...
go vet ./...
cd frontend
npm run generate
```

Tests ครอบคลุมไฟล์ต้นฉบับไม่เปลี่ยน, โฟลเดอร์ย่อยและชื่อภาษาไทย, นามสกุลตัวพิมพ์ใหญ่,
การข้ามชื่อซ้ำ, ไฟล์ที่ไม่ใช่ภาพ, โฟลเดอร์ซ้อนกัน, โฟลเดอร์ว่าง, ความล้มเหลวบางไฟล์,
การลบไฟล์คัดลอกไม่สมบูรณ์ และ symlink ออกจากปลายทาง (ข้าม test หาก OS ไม่อนุญาตสร้าง symlink)

ผลตรวจวันที่ 16 ตุลาคม 2026: `go test -count=1 -v ./...`, `go vet ./...`,
`npm run generate` และ `wails build -s -skipbindings` ผ่านบน Windows
โดย test symlink ถูกข้ามเพราะ Windows ไม่ให้สิทธิ์สร้าง symlink
ยังไม่ได้ทดสอบ GUI กับ flash drive/โทรศัพท์จริง หรือรันบน macOS
